03 — Pipeline

Search & Scoring Pipeline

End-to-end flow from trigger to scored, enriched job entries.

  1. Trigger — Manual (dashboard button) or cron (every 6 hours)
  2. Wave 1 — All API sources run in parallel (~5-10 seconds)
  3. Wave 2 — Query scrapers run sequentially with 2s delays
  4. Wave 3 — Niche boards run in parallel
  5. Deduplication — Normalized title + company name
  6. Scoring — 0-100 fit score (title match, seniority, marketing relevance, remote, AI keywords)
  7. Content Gen — Cover letter, LinkedIn msg, email outreach for each job
  8. Storage — Upsert into SQLite. Higher scores overwrite lower.

04 — Auto-Apply

Auto-Apply System

Greenhouse + Lever only. These have predictable form structures the Playwright agent can fill. LinkedIn, Indeed, and others require manual application.
  1. Select target tiers (A, B, C) and max applications
  2. System filters to unapplied Greenhouse/Lever jobs
  3. Jobs sorted by fit score (highest first)
  4. Playwright agent opens each form, fills fields, uploads resume, submits
  5. Status updated to "applied" with timestamp
  6. Success/failure logged to activity feed

08 — Deployment

Deployment SOP

Frontend (Vercel) — Auto-deploys on push

  1. Make changes in frontend/src/
  2. Test locally: cd frontend && npm run dev
  3. Build check: npm run build
  4. Commit and push to main
  5. Vercel auto-deploys from GitHub

Backend (Railway) — Manual deploy

  1. Make changes in backend/src/
  2. Test locally: cd backend && node src/server.js
  3. Copy changed files into frontend/backend/ (monorepo)
  4. Commit and push to GitHub
  5. Deploy: cd backend && railway up
Monorepo note: The frontend repo contains backend/ as a subdirectory. The standalone backend directory has its own git + Railway link. Always sync changes to both before deploying.

11 — Security

Security

  • CORS — Locked to Vercel frontend URL only
  • Helmet — Security headers on all responses
  • Rate Limiting — Per-endpoint limits
  • API Key Auth — All mutating endpoints require x-api-key
  • Input Validation — Title (100 chars), URL (http/https), notes (10K limit), links (max 20)
  • No secrets in frontend — Only VITE_API_URL exposed
